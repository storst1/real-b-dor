# Матчи FotMob и возможность назначать веса отдельным играм

Назначать веса отдельным матчам технически возможно без загрузки полной карточки каждой игры. Текущий адаптер уже получает матчевые оценки и контекст через историю игрока; теперь он сохраняет эти поля в `competitions[].matches`. Формула весов и новая оценка этим изменением не вводятся.

## Проверка реального источника

Проверено 25 ноября 2026 года: Harry Kane, Transfermarkt `132098`, FotMob `194165`, сезон `2023/24` с летним Евро-2024. Выполнены ровно шесть HTTP-запросов, все завершились с HTTP 200:

1. `search/suggest?term=Harry Kane` — поиск профиля.
2. `playerData?id=194165` — проверка личности и команды сборной.
3. Четыре страницы `playerMatches` по 20 записей.

Запрос истории использует маршрут `https://www.fotmob.com/api/data/playerMatches` и параметр `url`: адрес `https://pub.fotmob.com/prod/db/api/player/194165/matches?before=1725148800&leagueId=all&teamId=all`. Следующие страницы определяются числовым `before` из ответа `previous`. Адаптер проверяет адрес и сам собирает следующий URL.

Из 80 полученных записей после отбора периода, турниров, сыгранных матчей и удаления дублей выбраны **59 выходов на поле, все 59 с оценкой**. Полное выполнение заняло **1,261 секунды** в проверке обычным `httpx` без пауз общего транспорта приложения; это наблюдение одного запуска, не гарантия скорости.

## Какие сведения доступны без дополнительных запросов

| Поле сохранённой истории | Поле FotMob | Покрытие в проверке |
| --- | --- | --- |
| `id`, `date`, `kickoff` | `id`, `matchDate.utcTime` | 59 / 59 |
| `rating` | `ratingProps.rating` | 59 / 59 |
| `minutes`, `goals`, `assists` | `minutesPlayed`, `goals`, `assists` | 59 / 59 |
| `team_id`, `team` | `teamId`, `teamName` | 59 / 59 |
| `opponent_id`, `opponent` | `opponentTeamId`, `opponentTeamName` | 59 / 59 |
| `competition_id`, `competition` | `leagueId`, `leagueName` | 59 / 59 |
| `is_home` | `isHomeTeam` | 59 / 59 |
| `home_score`, `away_score` | `homeScore`, `awayScore` | 59 / 59 |
| `stage` | `stage` | 11 / 59 |
| `url` | `matchPageUrl` с доменом FotMob | 59 / 59 |

Оценки в истории представлены строками с **одним десятичным знаком**. Адаптер сохраняет их числами и считает среднее без дополнительного округления. Из-за точности исходных матчевых оценок такое среднее может немного отличаться от сезонной карточки FotMob.

Стадия была указана у 11 матчей: `1/8` — три, `1/4` — три, `1/2` — три, `final` — два. У остальных 48 игр значение `null`. Это позволяет отдельно обрабатывать известные финалы и раунды плей-офф, но не даёт основания считать неизвестную стадию групповой или рядовой.

`is_home` обозначает номинальную домашнюю сторону протокола. Признака нейтрального поля в проверенной истории нет. Явного поля победа/ничья/поражение также нет: обычный результат можно вывести из счёта и стороны игрока. Для корректного учёта серии пенальти нужны дополнительные сведения, которых в этих строках не обнаружено. Явный статус завершения матча в проверенных строках отсутствовал.

## Что остаётся определить отдельно

Готового численного показателя важности игры FotMob в истории не возвращает. Веса по турниру, известной стадии, противнику, минутам или номинальной стороне можно применять к сохранённым матчам локально после определения правил. Установить, насколько важен конкретный матч чемпионата для борьбы за титул, по этим полям нельзя: положение команд до игры и турнирный контекст в списке отсутствуют.

Для дополнительной информации существует используемый соседним проектом маршрут `matchDetails?matchId=…`. Его загрузка стоит один запрос на матч: запрос всех 59 карточек добавил бы до 59 обращений сверх шести запросов истории. Эта проверка карточки матчей не загружала. Для перечисленных доступных полей они не нужны.

Отсутствующие или некорректные дополнительные поля сохраняются как `null` и не исключают сыгранный матч. Нулевая синтетическая оценка запасного не превращается в настоящую оценку; выход без опубликованного рейтинга сохраняется с `rating: null` и не попадает в знаменатель средней. Существующие правила дат, периодов, дублей и подсчёта средней не изменены.

Расширенные строки появляются в результате следующего импорта или обновления FotMob. Старые записи, в которых уже сохранены только ID и дата, не содержат потерянный контекст: для его получения потребуется загрузить историю повторно.
